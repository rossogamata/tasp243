## 1. Поняття Docker Compose

**Docker Compose** — інструмент для опису та запуску застосунку, що складається з одного або кількох сервісів. Конфігурацію зберігають у YAML-файлі, найчастіше `compose.yaml`. Замість ручного запуску кожного контейнера з його портами, мережею та іншими параметрами достатньо описати проєкт і керувати ним командами Compose.

| Поняття | Значення |
|---|---|
| **Image / образ** | Шаблон, з якого створюють контейнер. |
| **Container / контейнер** | Ізольований екземпляр образу. |
| **Service / сервіс** | Опис контейнера та його налаштувань у Compose-файлі. |
| **Project / проєкт** | Сукупність сервісів, мереж і томів, якими керує Compose. |
| **Volume / том** | Сховище для даних, які мають пережити пересоздання контейнера. |

Compose за замовчуванням створює спільну мережу проєкту. Контейнери в цій мережі можуть звертатися один до одного за назвою сервісу. Наприклад, сервіс `web` під'єднується до Redis за адресою `redis:6379`. Для цього зв'язку не потрібно публікувати Redis-порт на хості.

У матеріалі використовується сучасна команда `docker compose` (через пробіл). Поле верхнього рівня `version` для сучасного Compose не потрібне.

## 2. Compose-файл

У каталозі заняття розміщено готовий демонстраційний проєкт:

```text
Lesson2_6/
├── README.md
├── compose.yaml
├── Dockerfile
├── app.py
└── requirements.txt
```

Основні частини `compose.yaml`:

```yaml
services:
  web:
    build:
      context: .
    ports:
      - "5000:5000"
    environment:
      REDIS_HOST: redis
    depends_on:
      redis:
        condition: service_healthy

  redis:
    image: redis:7-alpine
    volumes:
      - redis-data:/data

volumes:
  redis-data:
```

| Параметр | Призначення |
|---|---|
| `services` | Перелік сервісів застосунку. |
| `build.context` | Каталог, який Compose використовує для збірки образу. Тут поруч розташований `Dockerfile`. |
| `image` | Назва готового образу, який потрібно завантажити або використати локально. |
| `ports` | Публікація портів у форматі `порт_хоста:порт_контейнера`. |
| `environment` | Змінні середовища, передані контейнеру. |
| `depends_on` | Залежність сервісів; `service_healthy` очікує успішної healthcheck-перевірки залежності. |
| `volumes` | Під'єднання сховища до контейнера; верхній рівень оголошує named volume. |
| `healthcheck` | Команда та інтервал для перевірки готовності сервісу. |

### `build` та `image`

- `build: .` означає, що образ потрібно зібрати з `Dockerfile` у вказаному контексті.
- `image: redis:7-alpine` означає, що сервіс використовує готовий образ Redis.
- Один Compose-проєкт може одночасно збирати власний образ і використовувати опубліковані образи.

### Мережа, порти та томи

- `web` звертається до Redis за назвою сервісу `redis`, а не через `localhost`.
- `5000:5000` публікує порт вебзастосунку на хості. Сторінка доступна на `http://localhost:5000`.
- `redis-data` зберігає дані Redis поза файловою системою контейнера. Звичайний `docker compose down` залишає том; `docker compose down --volumes` видаляє його разом із даними.

## 3. Демонстрація: збирання та запуск проєкту

### Підготовка

Переконайтеся, що Docker Desktop або Docker Engine запущено, а команда Compose доступна:

```bash
docker --version
docker compose version
cd Lesson2_6
```

Перед запуском перегляньте конфігурацію, яку Compose побудував із YAML:

```bash
docker compose config
```

### Збірка і запуск

```bash
docker compose up --build
```

Compose збере образ `web`, завантажить образ Redis за потреби, створить мережу та том, а потім запустить обидва сервіси. Redis має перейти у стан `healthy`, перш ніж Compose запустить `web`.

Для запуску у фоні:

```bash
docker compose up --build --detach
```

### Перевірка результату

```bash
docker compose ps
docker compose logs
docker compose logs --follow web
```

Відкрийте `http://localhost:5000` або надішліть кілька запитів:

```bash
curl http://localhost:5000/
curl http://localhost:5000/
curl http://localhost:5000/health
```

Кожне звернення до головної сторінки збільшує лічильник у Redis. `/health` повертає стан застосунку та Redis. Щоб перевірити мережеву взаємодію, викладач може запустити команду всередині контейнера `web`:

```bash
docker compose exec web sh
```

У контейнері ім'я `redis` розв'язується у адресу сервісу Redis. Вийдіть командою `exit`.

### Зупинка

```bash
docker compose down
```

Команда зупиняє та видаляє контейнери й мережу проєкту, але зберігає named volume. Щоб почати з чистими даними, після попередження про видалення даних можна виконати:

```bash
docker compose down --volumes
```

Не використовуйте `--volumes`, якщо дані Redis потрібно зберегти.

## Демонстрація викладача: послідовність пояснення

1. Показати структуру каталогу та пояснити призначення `Dockerfile`, `app.py`, `requirements.txt` і `compose.yaml`.
2. Разом прочитати Compose-файл і визначити, який сервіс збирається локально, а який використовує готовий образ.
3. Виконати `docker compose config`, звернути увагу на YAML-відступи та розгорнуту конфігурацію.
4. Запустити `docker compose up --build` і співвіднести журнали з сервісами.
5. Перевірити сторінку, лічильник, стан сервісів та healthcheck Redis.
6. Пояснити різницю між портом хоста і портом контейнера та між `localhost` і DNS-іменем `redis`.
7. Зупинити проєкт через `docker compose down`; пояснити, чому том з даними лишився.

## Самостійна робота

Виконайте роботу в каталозі `Lesson2_6`. Запустіть демонстраційний проєкт, вивчіть його конфігурацію та внесіть зміни.

1. Виведіть конфігурацію командою `docker compose config`. Назвіть сервіси, порт публікації, змінну середовища, залежність і том.
2. Запустіть проєкт із перебудовою образу. Перевірте `docker compose ps` та журнали кожного сервісу.
3. Відкрийте вебсторінку й надішліть щонайменше п'ять запитів. Поясніть, де зберігається лічильник.
4. Зупиніть і видаліть контейнери командою `docker compose down`, запустіть проєкт повторно та перевірте, чи зберігся лічильник.
5. Змініть публічний порт вебзастосунку на `8086`, залишивши контейнерний порт без змін. Перезапустіть проєкт і перевірте `http://localhost:8086`.
6. Додайте у відповідь головної сторінки своє прізвище або інший погоджений викладачем ідентифікатор. Перебудуйте образ і покажіть результат.
7. Поясніть, що станеться з даними тому після `docker compose down`, `docker compose down --volumes` і видалення лише контейнерів.
8. Поверніть проєкт до стану, в якому його можна перевірити викладачеві, і покажіть команди запуску та зупинки.

## Типові помилки

- **Неправильні YAML-відступи.** Використовуйте пробіли, а не табуляцію; вкладені поля мають бути на відповідному рівні.
- **Звернення до Redis через `localhost`.** Усередині `web` це адреса самого вебконтейнера; правильне ім'я хоста — `redis`.
- **Неправильний порядок портів.** У `ports` спочатку вказано порт хоста, потім порт контейнера.
- **Відсутність перебудови після зміни файлів образу.** Для гарантованої збірки використовуйте `docker compose up --build`.
- **Очікування, що `depends_on` без healthcheck означає готовність застосунку.** Порядок запуску контейнерів не завжди означає готовність сервісу приймати запити.
- **Втрата даних через `down --volumes`.** Цей параметр видаляє named volumes проєкту разом із даними.
- **Зайнятий порт хоста.** Змініть перше число у `ports` на вільний порт і повторно запустіть Compose.
