# Приклад: правила мережевої безпеки

> Це зразок структури документа. Фактичні правила потрібно обґрунтувати та звірити з власною конфігурацією.

## Security Group

Security Group є stateful firewall на рівні мережевого інтерфейсу. Відповідний вихідний трафік для дозволеного вхідного з'єднання повертається автоматично.

| Напрямок | Протокол | Порт | Джерело або призначення | Дія | Причина |
|---|---|---:|---|---|---|
| Inbound | TCP | 80 | `0.0.0.0/0` | Allow | Навчальний HTTP-доступ |
| Inbound | TCP | 22 | Обмежена IP-адреса адміністратора | Allow | Тимчасове адміністрування |
| Outbound | All | All | `0.0.0.0/0` | Allow | Вихідні оновлення та відповіді |

## Network ACL

Network ACL є stateless firewall на рівні subnet. Тому потрібно врахувати і запит, і зворотний трафік.

| Напрямок | № правила | Протокол | Порт | CIDR | Дія | Причина |
|---|---:|---|---:|---|---|---|
| Inbound | 100 | TCP | 80 | `0.0.0.0/0` | Allow | Вхідний HTTP |
| Inbound | 110 | TCP | 1024-65535 | `0.0.0.0/0` | Allow | Ефемерні порти відповідей |
| Outbound | 100 | All | All | `0.0.0.0/0` | Allow | Вихідний трафік |

## Ризики навчальної конфігурації

1. `0.0.0.0/0` для HTTP відкриває сервіс усьому інтернету.
2. SSH не слід відкривати для `0.0.0.0/0`.
3. У production правила потрібно звузити до необхідних джерел.
4. NACL не замінює Security Group: вони діють на різних рівнях і мають різну модель стану.
